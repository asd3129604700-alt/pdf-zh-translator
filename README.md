# 英文资料中文转换器

把客户给的英文资料（PDF / 图片）译成中文，覆盖回原来的位置，导出中文版 PDF。

纯前端、零后端：不需要装环境，也可以丢到 GitHub Pages 上给别人用（见「使用 → 在线」）。

---

## 该用哪种识别引擎？

界面上有两个选择，**这个选择直接决定小字认不认得出来**：

| | 云端视觉模型（默认，推荐） | 本地 OCR |
|---|---|---|
| 原理 | 把图片交给视觉大模型识别并翻译 | 浏览器内 Tesseract 识别 |
| 小字 / 糊字 | **强** | 弱 |
| 彩底 / 艺术字 | **强** | 差 |
| 需要 Key | 需要 | 不需要 |
| 图片是否外发 | **会发到服务商** | 不外发，只把文字发去翻译 |
| 费用 | 按量计费，通常几分钱一张 | 免费 |

**如果你的素材是电子截图、规格表，而且文字边缘不够锐利（被缩放过、JPEG 压过），请用云端视觉模型。**
Tesseract 对这类"软边小字"先天吃力——它想要的是锐利的二值化笔画。视觉模型看这种糊字反而比它清楚得多。

> **识别引擎只作用于图片。**
> PDF 只要带文字层，就直接从文字层提取（又快又准），不会调用视觉模型，也不需要视觉模型的 Key。
> 所以处理纯 PDF 时，你只需要配「翻译方式」；只有图片才会用到识别引擎。
> 扫描版 PDF 请先把页面导出成图片，再用图片模式处理。

> 项目最初是纯 Tesseract 方案，靠"先探测文字区域，再逐块放大识别"来对付小字。
> 这个思路保留下来了，但**放大之后由视觉模型来认**，效果差别很大：
> 一个 6px 高的字符在整图里送到模型等于糊成一团，放大到 30px 就认得出了。

如果资料不能外发，就切到本地 OCR。它免费、可离线，但请把期望值放低。

## 使用

### 在线

**方式一：GitHub Pages（推荐，别人也能用）**

仓库根目录就是站点根目录，没有构建步骤，也不需要任何 CI 配置：

1. 把仓库推到 GitHub（public 仓库才能免费用 Pages；私有仓库 + Pages 需要 GitHub Pro）
2. 仓库 **Settings → Pages → Build and deployment → Source: Deploy from a branch**
3. Branch 选 **main**，目录选 **/(root)**，保存
4. 等一两分钟，访问 `https://<你的用户名>.github.io/<仓库名>/`

页面在一个子路径（`/<仓库名>/`）下工作，这一点已经验证过：`index.html` 引用的
12 个本地资源（css + 11 个 js）全部用的是相对路径，没有 `/` 开头的绝对路径，
也没有 `<base>` 标签，所以在子路径下能正确解析。仓库根目录还有一个 `.nojekyll`，
让它跳过 Jekyll 构建（快，而且不会因为文档里的花括号、下划线开头的文件出岔子）。

每个使用者需要**自己填 API Key**（填在页面上、存在各自浏览器的 localStorage 里）。
仓库里不含任何 Key，也不含任何图片素材。

**方式二：本机打开**

直接双击 `index.html`（`file://`）也能开，但功能是残缺的：
云端视觉识别可以用，**PDF 解析和本地 OCR 会失效** ——
它们依赖的 Web Worker 在 `file://` 下会被浏览器按跨源规则拦掉。

想在本机用完整功能，起一个静态服务即可：

```bash
node scripts/serve.js          # 默认 8770 端口
python -m http.server 8770     # 没有 Node 就用 Python
```

然后访问 `http://127.0.0.1:8770`。

### 隐私：图片会不会外泄

分两种情况，**取决于你选哪个识别引擎**：

| | 图片去哪了 | 文字去哪了 |
|---|---|---|
| 本地 OCR | **不出浏览器**，一个像素都不外发 | 识别出的文字发给翻译接口（Google/MyMemory 或你配的大模型） |
| 云端视觉模型 | **会发给你配置的那家服务商**（Gemini / OpenAI 兼容 / DeepSeek…） | 同上 |

云端视觉模型这条路，图片必须发给服务商才能识别 —— 这是原理决定的，不是实现取巧。
所以：**资料不能外发就用本地 OCR**；要用云端模型，就用你被允许接收这份资料的那家。

另外几点：

- 本项目**没有后端、没有埋点、没有统计**。页面只在你点「开始转换」时才发请求，
  请求目标就是你自己填的那几个地址。
- 仓库里**不含任何图片素材**：`.gitignore` 明确挡住 `*.jpg *.png *.pdf` 等，
  客户资料放在仓库外，不会被提交。
- 仓库里**不含客户专有词**：自带的「玩具 / 产品规格表」词表只有行业通用词
  （材质、工艺、部件、尺寸）。你自己的那份放 `glossary.local.txt`（见下），
  它被 `.gitignore` 挡住，不会进仓库、也不会被发布。

### 私有术语表（不进仓库）

`js/config.js` 里那份词表是要公开的，所以只放行业通用词。你自己那套带客户原话、
品牌名、角色名的词表，放在仓库根目录的 **`glossary.local.txt`**：

```text
# 每行一条     原文 => 译文
# 右边写「原样」= 保持英文不翻译
SEPARATE PIECE => 独立部件
EMBROIDERY => 刺绣
```

页面启动时会自动尝试加载它，加载成功就覆盖「玩具 / 产品规格表」预设里的通用词表；
加载不到（别人机器上没有这个文件、或者你用 `file://` 打开）就安静跳过，用通用预设。
两个场景都不需要你手动做任何事。

这个文件已经在 `.gitignore` 里，`git add -A` 不会把它带上；
`test/test-api-shape.js` 里也有断言守着（私有词表必须被 ignore、自带词表里不许出现
品牌词和客户整句），防止以后有人又把它写回代码。

### 步骤

1. 拖入 1 个 PDF，或者多选 JPG / PNG / WebP
2. 选识别引擎
3. 如果选了云端视觉模型：填 Base URL、API Key、模型（点「拉取模型列表」拿真实可用的模型 ID）
4. 需要的话展开「领域与术语表」，填上这个客户/行业的专有词
5. 点「开始转换」
6. 结果页可以对照原稿、悬停列表条目会**在图上框出对应位置**，方便核对
7. 下载中文 PDF

### 选项说明

- **保留型号 / 色号 / 尺寸代码**：默认开。让 `PMS 1234 C`、`4'5"`、`160cm` 这类内容不被翻译。
- **字段按类型上色**：默认**关**。开启后按字段类型给中文上色 ——
  标签/表头=深蓝、型号/色号/数值=品红、说明句=深绿，便于在密密麻麻的规格表上扫读。
  深色底上**不上色**（固定色在深底上的对比度没保障，宁可保持从原图采样出的字色）。
  默认关闭是因为它会改变原文档观感，交给客户前可能不合适。

界面上选了服务商会自动带出申请链接，常用的几个：

- **Google Gemini** — <https://aistudio.google.com/apikey>（识别小字能力强，性价比高）
- **通义千问 Qwen-VL** — <https://bailian.console.aliyun.com/>（国内直连）
- **智谱 GLM-4V** — <https://open.bigmodel.cn/usercenter/apikeys>（国内直连）
- **硅基流动** — <https://cloud.siliconflow.cn/account/ak>（一个 Key 切多家开源视觉模型）
- **OpenAI** — <https://platform.openai.com/api-keys>

任何兼容 `/chat/completions` 且支持图片输入的服务都能填在「自定义」里。

> **注意**：预设里的模型 ID 只是**起始值**，供应商更新很快。
> 请以「拉取模型列表」的结果为准，或者手动填你账号里真实存在的模型 ID。
> 填错模型 ID 会直接报 400 错误。

## 领域与术语表

原版把某个客户的品牌 / 角色词表**写死在代码里**，系统提示词也是「你是玩具/产品规格图译者」。
换一份普通客户资料就会翻得不对劲。现在这部分全部挪到了界面上：

- **领域预设**：`通用文档`（默认，不含任何预设词）/ `玩具 · 产品规格表`（通用行业词）/ `自定义`
- **背景说明**：一句话告诉模型这是什么资料，会拼进提示词
- **术语表**：每行一条，`原文 => 译文`

术语表写法：

```
# 井号开头是注释
Material => 材质
SEPARATE PIECE => 独立部件
PANTONE => 原样          # 右侧写「原样」表示不翻译，保持英文
PMS                      # 只有原文、没有 => 也按「保持原样」处理
```

长词优先匹配，带斜杠（`Silk/Sateen`）、点号（`DEV. STAGE`）的词都能正确处理；
`Back => 背面` 不会把 `Backpack` 误伤成 `背面pack`。

**术语表只影响提示词和译后替换，不影响识别。**

用 Playwright + Chromium 在本机浏览器里验证过：

- `index.html` 加载后 **0 个 console 错误、0 个未捕获异常**，9 个模块全部就位
- UI 联动正确（切引擎时配置区显示/隐藏、视觉模式下「翻译方式」被禁用并说明原因）

- 用**真实素材**跑本地 OCR 端到端：小字样例读出 `SIZE CHART SMALL TEXT`、`Length: 68 cm /26.8 in`、
  `SKU: PL-2024-OR-M` 等（置信度 82~96%）

> 这一步抓到过一个只有真实端到端才能暴露的 bug：Tesseract 的 TSV 里**行级（level=4）

> 单测当时没抓到，因为 fixture 里把行级 conf 写成了 92.5（编的），而不是 -1（真实的）。
> 现在 fixture 照真实输出抄，并加了回归断言。

带上 `selftest.html` 在浏览器里打开，可以**逐环节**验证流水线：

1. 环境检查——确认所有模块和外部库都加载了
2. 生成一张合成测试图——刻意做成了你的素材的样子（干净但文字边缘糊）
3. 文字区域检测——本地算法，看找到几行、耗时多少
4. 本地 OCR 端到端——会下载语言数据，需要联网
5. 排版与覆盖——看中文有没有溢出压到别的行
6. 云端视觉端到端——用你自己的 Key 跑真实请求（会计费）

任何一步出问题，这个页面会直接告诉你卡在哪一环。

## 实现说明

架构和模块接口写在 **[`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md)**。

一句话概括：`检测文字区域 → 逐区域放大识别 → 翻译 → 统一排版引擎覆盖回原位 → 导出 PDF`。
PDF 和图片在"排版"这一步合流，共用同一套覆盖逻辑。

```
js/util.js        几何、文本比对、并发池、中止、大模型输出解析
js/config.js      供应商预设、领域配置、提示词构建   ← 换领域只改这里
js/imageproc.js   灰度、积分图、自适应二值化、反锐化掩膜
js/detect.js      纯 JS 文字区域检测（连通域 → 行 → 区域块）
js/vision.js      云端视觉模型客户端（Gemini / OpenAI 兼容）
js/ocr-local.js   本地 Tesseract（多 worker 并行 + 按字高分组的条带）
js/translate.js   翻译（免费接口 / 大模型 / 术语表），型号与代码保护
js/overlay.js     中文排版与覆盖（唯一一套，防溢出压字）
js/pdf-engine.js  pdf.js 提取与渲染、jsPDF 导出
js/app.js         控制器：流水线编排、进度、取消
glossary.local.txt 本机私有术语表（可选，不进仓库）
```

### 几个值得说明的设计决定

- **检测和识别分离**。原版用 Tesseract 自己做版面探测（多尺度全图 OCR 最多 3 次 + 64 个区域 + 1 次救援 = 单图最多 68 次串行调用）。现在检测是纯像素算法，几十毫秒出结果（实测 1600×1200 满页文字 46ms），Tesseract 只负责认字。
- **条带按行高分组，各自决定放大倍数**。放大后字高统一逼近 32px（LSTM 的舒适区），所以 8px 的小字放大 4 倍，24px 的字放大 1.3 倍——而不是所有区域共用一个倍数。
- **反锐化掩膜**。原版只做了全局灰度拉伸，没让边缘变锐；再用双线性插值放大只会更糊。`放大 → 反锐化` 才是让糊字能被认出来的正路。锐化强度还会根据图的清晰度自动决定。
- **检测结果有多遍兜底**。云端识别是「逐区域放大识别」+「整图兜底识别」两遍再合并去重。整图那遍专门用来捡回检测漏掉的文字——漏字是用户最不能接受的失败方式。
- **排版按框索引，不按文本索引**。原版用 `map[原文]` 做映射，同一段英文出现两次会被强制翻成同一个结果，还会互相覆盖。
- **覆盖范围受邻居约束**。先算每个文字框上下各有多少可用空间，再决定字号，最后裁剪到允许区域内。原版允许中文块长到原文高度的 2.2 倍且不做任何检查，密集表格上必然压字。
- **中文字号默认比原文大**。中文比英文短，框里本来就有余量；而且排版量到的"原文行高"是**墨迹高度**，西文只有字号的 ~0.7 倍，照搬会让中文小一圈。
- **同一行上挨得近的碎块先并成一条**。上游常把一行切成好几块（标签一块、数值一块），分开排版时它们会互相夹住擦除范围和字号 —— 表现就是"贴不全 + 有的字小"，而孤立的块完全正常，看起来毫无规律。合并后原文用空格连接、译文按语言习惯连。
- **折行宽度用"到右侧干净空白为止"的空间**，不是原文墨迹的宽度。中文一个字占一个全角宽（12 个汉字 = 12em，12 个字母只有 ~6.6em），照墨迹宽折行会被折成好几行、撞上高度上限、只能缩字号。"干净"是逐列看像素判的：右边有表格线或图案就停下，宁可字小也不横穿线条。
- **底色用"框外一圈的众数"，不是均值也不是逐列插值**。均值会被框外扫到的图案拉偏；众数问的是"这一圈里最常见的颜色是哪个"，那才是背景色。有了底色，去字就只需要动"与底色不同的像素"。
- **失败就报错，不静默降级**。API 调用失败会明确告诉你失败在哪一步，而不是悄悄换成免费接口让你以为翻译成功了。

### 相对原来（v2）改了什么

| 问题 | 原来 | 现在 |
|---|---|---|
| 图片小字识别 | Tesseract 多尺度探测 + 逐块放大（最多 68 次串行 OCR） | 纯 JS 检测（46ms）→ 按行高分组的条带 → 3 个 worker 并行 |
| 视觉模型 | 只有 Gemini，固定 2/4 切块，无整图兜底 | Gemini + 任意 OpenAI 兼容视觉接口；区域放大 + 整图兜底 + 合并去重 |
| 领域绑定 | 词表和提示词硬编码某个客户的品牌 / 角色词 | 全部搬到界面上（领域预设 + 背景说明 + 术语表），算法层零领域词；自带预设只含行业通用词，客户词表放仓库外的 `glossary.local.txt` |
| 导出 PDF 清晰度 | `k=1600/pxMax` 把画布缩小贴上页面，A4 等效只有 **89 DPI** | 保持 PDF 原始页面尺寸，`72 × 渲染倍率` = **180 DPI** |
| 中文压字 | 允许长到原文高度 2.2 倍且不检查邻居 | 先算可用空间，再定字号，最后裁剪 |
| **去字（涂抹痕迹）** | 刷一块采样底色的矩形补丁；背景是渐变/图案时就是一块看得见的涂抹 | 默认 **只擦文字（ink）**：识别出底色后，只把"与底色不同的像素"涂成底色，底色/图案/线条原样不动，中文背后没有任何贴纸；阈值按底色纯度自适应，另有一套"薄带"判据保护表格线与插画（详见 `docs/ARCHITECTURE.md`）。另可选「整块填充」「智能修复」 |
| **中文字号** | 照搬原文墨迹高度，中文比英文小一圈 | 允许比原文大（默认 ×1.35，界面可选 跟随原文/稍大/更大/最大），因为**中文一定比英文字数少**，横向本来就有余量；装不下时自动降字号，不会压到邻居 |
| **排版观感** | 行高 1.16 偏松；一律左对齐；只靠缩字号来适配 | 行高收紧到 1.02；识别并**保持原文的左/中/右对齐**；宽度差一点时先收紧字距而不是掉一档字号（做法参考 ShinobuTranslator） |
| **重复翻译** | 去重只看文本相似度，短标签差一个字母就漏网 | 增加**几何去重**：位置重合就合并，与文本像不像无关；两条重叠的 item 会让后一条的底色盖掉前一条的中文，看起来就像写了两遍 |

## 已知限制

- **导出的 PDF 是位图，没有文字层**：中文是栅格化贴上去的，所以**不能搜索、不能选中复制**，文件也比原 PDF 大。要在 PDF 里嵌入可选中的中文，需要嵌入整个中文字体子集（通常几 MB），目前没有做。
- **扫描版 PDF 会自动按图片处理**：没有文字层的页面会被渲染成图片，走图片识别那条路（所以识别质量取决于所选识别引擎）。想要最好的效果，请把识别引擎切成云端视觉模型。
- **本地 OCR 的识别率有天花板**：Tesseract 对彩色背景、艺术字、严重模糊的小字都很吃力。这类素材请用云端视觉模型。
- **本地识别引擎对"混色底"有结构性盲区**：一张图里同时有「浅底深字」和「深底浅字」（例如规格表上带深色标题栏）时，检测环节只能按全局多数极性处理，**深色面板里的浅色字会被整体漏掉**。这只影响本地 OCR 路线；云端视觉模型不受影响（整图兜底那一遍照样能看到），所以有深色标题栏的资料请用视觉模型。这是当前检测器已知的最大短板，代码里 `js/detect.js` 有说明。
- **中文排版是原位替换，不是重排版**：译文放在原文的位置上，必要时缩小字号。没有做"整页重新排版"。
- **翻译质量取决于翻译源**：免费公共接口（Google / MyMemory）对长句和术语的处理明显弱于大模型。要求高的话请用大模型翻译。
- **首次使用本地 OCR 需要联网**：要从 CDN 下载 Tesseract 引擎和语言数据（约 10~15 MB）。下载完成后会缓存在浏览器里。
- **模型 ID 会被服务商改动**：预设只是起始值，请用「拉取模型列表」确认。

## 隐私

- **本地 OCR 模式**：图片不出本机。文字识别在你的浏览器里完成，只有 OCR 出来的**英文文本**会发给你选的翻译源。
- **云端视觉模式**：**图片本身**会发给你配置的视觉模型服务商。处理敏感资料前请确认对方的隐私政策。
- **API Key** 保存在浏览器的 `localStorage` 里，不会上传到任何地方。但请注意它是**明文存储**的——不要在共用电脑上保存 Key，用完可以清空输入框（保存时会存成空值）。
- 仓库里不含任何客户资料、截图或测试素材，`.gitignore` 已经把所有图片和 PDF 排除在外。
